# dns-check

Squad beyond の配信ドメインが正しく設定されているかを、顧客自身が確認できる公開ツールです。

**このツールはDNS設定を変更しません。** 現在公開されている情報を読み取って表示するだけなので、何度実行しても安全です。

## 使い方

1. 確認したいドメインを入力する（例：`sb.example.co.jp`）
2. 「サブドメインで配信」か「本ドメインで配信」を選ぶ（ドメインを入れると自動で選ばれます）
3. 「確認する」を押す

判定結果、DNSの管理元、実際に登録されているレコードが表示されます。結果はプレーンテキストでコピーできるので、そのまま問い合わせに貼り付けられます。

## 表示される内容

### 1. 判定

必要な設定と現在の設定を並べて、一致 / 不一致 / 未設定を判定します。

| 配信方法 | 種別 | TTL | 内容 |
|---|---|---|---|
| サブドメイン（ホスト名は `sb` 推奨、任意） | CNAME | 3600 | `fallback.mysquadbeyond.com` |
| 本ドメイン | A | 3600 | `104.16.117.60` |

TTL は表示のみで、判定には使っていません（3600以外でも配信は動作するため）。

### 2. DNS管理元

**このツールを作った一番の理由がここです。**

ドメインを買った会社と、DNSレコードを実際に管理している場所は別々にできます。この2つがずれていると、「設定したのに反映されない」が起きます。

例：お名前.comで取得したドメインのネームサーバーが AWS（Route 53）を向いている場合、お名前.comの「DNSレコード設定」画面でレコードを追加しても、参照されるのは Route 53 側なので何も起きません。制作会社がサイト構築時にネームサーバーを変更していて、顧客本人がそれを知らない、というケースで頻発します。

そこで、ゾーン頂点の NS レコードを引いて「どこで設定すべきか」を名指しで表示します。

判定できる事業者：

- お名前.com（`*.dnsv.jp`）
- お名前.com レンタルサーバー（`*.gmoserver.jp`）
- Amazon Route 53（`*.awsdns-*`）
- Cloudflare / さくらインターネット / エックスサーバー / ロリポップ / heteml / ムームードメイン / バリュードメイン / ConoHa / Azure DNS / Wix

一覧にない事業者の場合は事業者名を出さず、NS の一覧と汎用の案内文を表示します。NS のドメイン名から顧客側で判断できることが多いためです。

追加する場合は `NS_PROVIDERS` に `[正規表現, 事業者名, 案内文]` を足してください。

### 3. レコード一覧

CNAME / A / AAAA / TXT / MX / CAA を、値と TTL 付きで表示します。

## 確認できないこと

- **SSL証明書の状態**（発行者・有効期限など）。ブラウザから証明書を直接確認する手段がないため。証明書エラーの調査には別途サーバー側の仕組みが必要です
- **DNSの伝播状況**。公開DNSにキャッシュされた応答を見ているため、設定直後は古い値が返ることがあります
- **社内ネットワーク固有の名前解決**。社内DNSで別の値を返している場合、このツールの結果と実際の見え方は一致しません

## 設定値の変更

`index.html` 内の `PRESET` を編集してください。

```js
var PRESET={
  sub:{type:'CNAME',value:'fallback.mysquadbeyond.com'},
  apex:{type:'A',value:'104.16.117.60'}
};
```

## 構成

- `index.html` — 単一ファイル。ビルド不要、依存パッケージなし
- DNS問い合わせは DNS over HTTPS。Cloudflare（`cloudflare-dns.com`）を優先し、失敗時に Google（`dns.google`）へフォールバック
- 問い合わせは閲覧者のブラウザから直接発行されるため、サーバーもログも不要
- NS はゾーンの頂点にしか存在しないため、`sb.example.co.jp` を入力しても `example.co.jp` に対して問い合わせます。`co.jp` のような2階層TLDにも対応

## デプロイ

静的ホスティングにファイルを置くだけです。Cloudflare Pages / GitHub Pages の場合、ルートに `index.html` があれば動きます（ビルドコマンドは不要）。

顧客が「これは公式のツールか」と迷わないよう、`squadbeyond.com` 配下のサブドメインか、FAQサイト配下に置くことを推奨します。

## 動作確認

`index.html` をブラウザで直接開けば動きます（`file://` でも DoH は動作します）。
